## 摘要

研析面向阅读、整理和比较科研文献的连续操作，提供从 PDF 入库、检索问答到引用回看、研究计划生成的本地工作台。系统采用 React 与 FastAPI，使用 SQLite 保存文献、逐页正文、向量及任务状态，在四张 RTX 2080 Ti 上运行 Qwen2.5-7B-Instruct、multilingual-e5-small 与 EasyOCR。模型只读取本地权重；论文检索和下载访问 arXiv 官方服务，推理不调用云模型。

系统以可回看的原文作为输出依据：回答附物理页码和摘录，摘要综述检查所选文献覆盖，引用网络保存参考文献位置，任务失败保留检查点。验证分别覆盖隔离行为测试、真实模型样例、PDF 身份与证据区间，以及独立 GPU 环境复现。结果说明既定链路可以运行，不构成通用准确率、零幻觉或全部需求完成的证明。

## 1. 需求与设计目标

科研阅读常涉及多种 PDF 版本、扫描件、中英文术语及跨论文对比。单独生成一段答案不能解决来源确认、版本误用和结果复查的问题，因此本项目将文献身份、原文定位和模型输出放在同一工作流中。

核心需求有四项：一是保留原文件，管理解析状态和相似版本；二是从明确文献范围检索证据，回答后能回到物理页；三是衔接检索、翻译、图谱和研究计划，减少重复操作；四是在既有显卡条件下部署，并保留运行、失败和恢复的证据。验收同时关注成功路径及拒答、归档、版本冲突、模型未就绪等边界。

产品采用单实例、共享文献库的部署方式，优先服务少量用户的研究操作，不以高并发平台为目标。已有解析正文导航和来源检查，但不将其表述为完整 PDF 排版理解、学术事实审查或自主科研代理。需求范围与已知边界分别见证据[1]、[3]。

## 2. 系统架构与数据流

前端负责文献选择、任务状态、正文阅读、结果编辑与导出；FastAPI 提供上传、解析、检索、推理及来源检查接口。原始 PDF 以文件 SHA-256 标识，SQLite 保存文献元数据、物理页正文、解析方式、坐标、切块向量、来源及任务记录。页面和 API 同源提供，减少部署配置分散。

主处理链如下：

```text
PDF → 文本层／OCR → 按页切块与E5编码 → 版本候选／确认
确认有效版本 → E5＋BM25混合检索
问题 → 检索词扩展 → RRF 证据合并 → 本地回答 → 来源检查 → 原页回看
```

逐页解析采用单工作线程和有界排队；模型请求共享推理锁，避免多个任务同时挤占模型显存。原文、解析结果和缓存分开保存，重启后读取持久化数据。归档或版本替换不会删除原件，也不会把待确认版本混入问答。写作、图谱和导航使用文献快照或指纹，原文变化后要求重新核对。[1]

## 3. AI 技术选型、集成与优化

### 3.1 模型分工

| 组件                         | 本地模型／精度              | 四卡分工      |
| ---------------------------- | --------------------------- | ------------- |
| 问答、检索词转换、翻译与计划 | Qwen2.5-7B-Instruct，FP16   | GPU 0、1 分片 |
| 中英文语义检索               | multilingual-e5-small，FP32 | GPU 2         |
| 扫描页文字识别               | EasyOCR 英中识别            | GPU 3         |

这一组合复用同一生成模型完成多种语言任务，以较小向量模型承担召回，以独立 OCR 处理无文本层页面，适配现有四张 11 GB 显卡。选型依据是本地运行条件与已完成集成，并未进行足以证明最优性的模型横向评测。启动使用离线加载选项，模型文件清单另存 SHA-256；下载权重属于准备阶段。[1][2]

### 3.2 检索与回答约束

页面按约 1100 字符切块，重叠 160 字符，保留页码和偏移。E5 使用 query／passage 前缀，向量归一化后持久化；BM25 补充术语和精确词匹配，再以 RRF 合并前六段证据。中文问题可由本地模型扩展检索词，明确图号、训练硬件或比较维度时，有限规则补充相应正文，而非依赖模型记忆补数。[1][4][5]

生成结果采用逐条结论和单一来源编号。服务端拒绝范围外编号，检查摘录是否匹配当前原文、结论中的阿拉伯数字是否在对应摘录出现，并返回真实文献与页码。摘要综述分篇生成后合并，要求纳入范围全部覆盖。这些措施使可检测的引用和数值错误显式失败，但数字存在不等于语义成立，仍需阅读原文。

### 3.3 资源与稳定性优化

实机 FP16 eager 注意力曾出现非有限数值，改用 SDPA 后恢复；没有以该显卡不支持的 BF16 或 FlashAttention 为运行前提。分卡加载、单进程服务、推理互斥和有界队列控制资源占用。翻译与下载采用缓存及检查点，避免重复处理已通过的内容。取消在当前推理段或已提交的单篇操作结束后生效，不强杀模型线程。独立 GPU 复现确认了实际执行，而非仅以就绪状态代替运行证据。[2]

## 4. 六个业务模块实现

### 4.1 文献解析与版本管理

上传后先核对文件头、大小和 SHA-256，改名上传相同字节仍复用原文献。当前单文件上限 100 MB、650 页。原生页面用 pypdf 提取；缺少可靠文本层时走本地 OCR，并保存文字、坐标、置信度及警告。正文词组与 E5 相似度产生版本候选，用户选择保留两版、保留旧版或替换旧版，决策留下记录，归档可恢复。

已对 541 页教材进行原件哈希、完整索引及逐页解析结果一致性核对，并保留数学字体与复杂内容警告。完整页数不表示图表、公式全部结构化。资料目录有 39 份 PDF 清单，当前测试不覆盖每份文献的所有问题，更不能由若干扫描样例推导 OCR 准确率。[3]

### 4.2 有证据的文献问答

用户明确选择文献范围后，系统仅检索有效、已就绪且未归档的正文。通用问题走本地检索与 Qwen；能够严格核对的结构问题采用保守处理器。例如作者序号须与首页线性署名一致，机构缺失时不由邮箱猜测；BLEU 表格按列坐标读数，差值单独标注计算；双篇编码器／解码器对比可由明确原文作确定性归纳。

连续追问仅继承上一次有效回答的文献身份；“其中”“这篇”等指代在该范围重新检索，用户显式选择优先。新对话、切换范围、拒答或请求失败会清空关联，原文被归档或替换时不悄悄退回全库。不将历史模型答案当证据。实机依次问作者、Adam参数和训练显卡，均回到同一原文。[15]

官方样例曾出现作者顺序错误和硬件段漏召回，修复后五个固定问题及八项补充检查通过。GPT 参数、上下文和归一化比较分别取证，避免把不同论文数字拼到同一来源。确定性处理器与模型路径在报告中分开，不把规则答案计作生成模型通过。[4][5]

### 4.3 沉浸阅读与对照翻译

阅读界面并排展示原页和解析正文，支持显式编号三级章节导航，以及数字制、有限英文作者年份制的正文引用与书目双向定位。链接保存物理页、字符区间和页哈希；歧义年份、未知编号和无法可靠切分的书目不自动连接。当前交互发生在解析正文，尚无 PDF.js 图像上的文字覆盖层。

新增原生页按需结构提取：表题及水平线限定表格区域，按完整单词与列坐标保留空格及跨列；科学计数法依据字形大小与上移位置标记指数，提供CSV、原图、坐标与原页入口。编号公式以右侧编号与邻近数学符号定位，提供原排版裁剪图和文本转写，不冒充任意LaTeX重建。处理采用45秒超时子进程与独立版本缓存；扫描页继续使用GPU OCR和原页，不自动填补复杂表格。[18]

翻译按源段编号对照，双向滚动可联动。数字、可识别公式、代码和网址先保护再恢复；校验失败缩短或拆分重译，仍失败则中断并保留通过段落。新增默认关闭的正文悬停/点击/键盘翻译：PDF软换行不作为句末，服务端核对Unicode字符区间与页面原文；每组件一个选段任务、按原句/语言会话缓存，切页或换语言不显示旧结果，公式代码片段保留。Transformer第3页完整原句实机通过，point-wise仍有混合术语译法，不能据此声称术语语义完美。[20]Ragas 八页、39 段的真实翻译与导出已有记录；这不是通用语义质量评测，541 页教材的全量翻译仍未验收。[6][9]

### 4.4 论文检索与来源入库

arXiv 查询限定官方元数据与 PDF 来源，设置请求间隔、大小和下载预算。中文主题先转换为英文，E5 可按当前主题重排首批最多八个候选，保存官方原序号、相似度与选择方式；无向量模型时退回明确标注的官方顺序。相似度不是相关概率或论文质量评分，也不表示全库召回。

入库复用下载和解析队列，保留实际 arXiv 版本与来源。官方元数据用于 arXiv 题名，原文件不改写。过期缓存可提示查看，但不能作为自动导入的有效依据。已增加每日/每周主题订阅，服务内调度到期查询，重启补一次；每轮取最新8篇，并用库内摘要E5关联给出推荐理由。用户反馈保存并调整当前列表顺序，不声称训练式学习。论文代码链接来自作者摘要/备注，未验证可复现性。[17]

书目下载解析明确arXiv/CoRR abs编号及官方链接；无编号书目可按题名向官方arXiv查询最多8个候选，规范化完整题名、作者姓氏/给名首字母及兼容年份共同核对，唯一作品才加入可下载列表。结果保存原文指纹与官方来源，歧义/未知或原文变更不会直接下载；仍需用户勾选，每批最多30篇，按队列入库，保留取消与重试检查点。真实匹配Transformer中的ResNet及Adam后下载12/15页，66/66与49/49段写入E5向量；1997年LSTM未匹配则不下载。仅覆盖可在arXiv核对的书目，未收录或复杂题名仍需手动获取。[19][17][7]

### 4.5 引用图谱与研究线索

图谱在参考文献区间匹配完整题名、arXiv 编号或 DOI，跨页保存证据；正文普通提及不直接构成引用边。同作品版本合并后计算局部入度、出度与 PageRank。题名边界用于排除 RMSNorm 题名后缀误连 LayerNorm，附录边界用于避免把后续正文当书目。

20 篇、816 页样本形成 100 条有向边；人工复核候选中的 100 个正例覆盖、两个混淆负例拒绝。该集合没有盲审全部 380 个有向对，因此不能写成一般引用召回率。局部排名仅反映当前网络，不等于全球影响力。Future Work 保留原文线索；新增按用户主题检索最新至多8篇arXiv候选，以E5重排后对至多4篇较新摘要作本地Qwen概括，与原方向原文一起展示。仅保留原文最近已知年份之后发表的候选，过期缓存及原文指纹变化会拒绝；支持JSON导出。这是有限摘要对照，不声称已判定方向是否解决，更不能证明首次提出。[18][8]

### 4.6 研究计划与可视化

写作工坊根据研究设想和最多六篇作品的明确摘要，生成可编辑研究计划、相关工作和真实书目。已有结论与拟开展方法、评估计划分开；References 由服务端元数据组织，不让模型自由补造 DOI 或作者。原文指纹变化后旧来源检查失效，手改内容标明编辑状态，不沿用生成时的检查结论。

方法步骤可导出 Mermaid 与 SVG；标签作为数据转义，不执行生成代码。图表支持首列类别及1-6列数值，分组柱状、多折线与雷达图，导出SVG和逐列图注。雷达限3-12个非负指标行，共用零起点和全局最大值，不自动归一化；指标单位和方向需可比较，未做显著性检验或多维统计推断。[18]研究计划不是完成实验的论文，也不证明新颖性。独立Chromium已实际下载研究计划、来源JSON、Mermaid、SVG及CSV图表/图注，检查内容与输入一致，并核对编辑后刷新恢复。[10][15]

## 5. 有界研究任务

任务将“主题检索—候选选择—逐篇入库—等待解析—摘要综述”串联，最多三篇、一个活动任务。SQLite 保存原始查询、候选、下载任务、文献身份、过程和结果。版本冲突暂停为待确认；模型未启动、缺摘要或覆盖校验失败时保留文献并进入待生成综述，可从检查点重试。服务重启不会隐式重新下载或推理。

中文主题“检索增强生成的自动评估”真实执行后，E5 在当前页选中官方第 4、6 名，分别为 45 页和 7 页文献。报告摘要位于物理第 5 页，旧首页规则漏检；覆盖检查拦截后，改为在前八页寻找明确摘要并排除目录项，最终两条结论分别回到第 5、1 页摘要。重试复用下载身份，旧 RAG 任务也成功补生成。历史完整任务读取时还会核对当前文献来源指纹；摘要缺失或来源失效显示待补生成，旧结论在响应中隐藏，数据库历史保留，重试复用原文和检查点。此结果是一次主题样例，不是自主规划、完整会话记忆或完整 Agent。[7][15]

## 6. 技术与应用创新设计

技术层面，第一项特点是统一文献身份、物理页、原文区间和快照，让问答、导航、图谱与写作共享可追溯依据；第二项是模型生成与有限确定性处理器分工，能严格读取的作者序号、表格数值与明确架构事实优先核对；第三项是多篇摘要覆盖检查及检查点恢复，来源不足时保留数据并拒绝半份综述。

应用层面，检索到的文献可直接进入阅读、翻译、关系浏览和研究计划，任务状态与版本确认避免用户重复搬运资料。四卡本地部署则把外部论文获取与内部推理分开。这些属于集成、交互与可靠性方面的工程设计，未提出新的训练算法，没有自行训练基础模型，也不主张领先现有科研工具或达到 SOTA。对应实现及测试见证据[1]、[6]—[10]。

## 7. 测试方法与实际结果

测试分为隔离行为测试、真实数据验收和环境复现三层。隔离测试使用替身验证路由、状态和拒绝条件，不冒充模型能力；真实样例检查模型输出及原文；复现检查独立代码和包环境是否能执行同一处理链。工程基线的后端测试192项、前端测试25项通过，包含真实React组件回归和前端工具测试；另有生产构建与格式检查。独立Chromium不使用API替身，真实访问四卡隔离库，12组页面流程及9个导出文件落盘核对通过。此前10组API联合回归单独保留，不把历史测试数相加为当前总量。新增主题订阅浏览器验证获取8篇最新结果、保存反馈、暂停，服务重启后自动补到期刷新并保留批次；该次补查询复用有效缓存，不将其描述为实际运行一周。[1][11][15][17]

## 8. 部署、访问控制与复现

部署采用 Python 3.12、Node.js 22.18 以上和匹配的 GPU 环境。先按锁定依赖安装，构建前端，下载并核对外置权重，再在环境变量中配置模型与数据目录。模型、PDF、数据库和实际密钥不进入 Git。正式服务单进程运行，可由用户级 systemd 管理；变更前备份数据，结束无任务时停止服务释放 GPU。[1][2]

### 8.1 安装与启动步骤

Ubuntu 服务器先准备 Python 3.12、Node.js 22.18 以上、匹配的 NVIDIA 驱动与 Poppler（pdftoppm）。在项目根目录执行：

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python \
  -r backend/server-environment.lock.txt \
  --extra-index-url https://download.pytorch.org/whl/cu130
npm ci
npm run build
cp .env.example .env
```

准备阶段可用 scripts/download_models.py 下载 Qwen 与 E5、scripts/download_ocr.py 下载 OCR，或复用已核对的外置文件。按模型清单核对哈希后，在 .env 设置三个模型的绝对路径、E5 的 cuda:2、OCR 的 cuda:3，以及 YANXI_LLM_SHARD=1。源码中的 Qwen 分片配置使用 GPU 0、1；保持四卡可见且编号对应，再执行 bash scripts/serve.sh。下载阶段联网，服务启动后只读本地权重。[1][2]

验收先检查 /api/health 的三类模型状态，再执行隔离库 GPU 脚本并核对实际回答、页码和向量，不将 health 代替功能验证。独立复现的具体命令见证据[2]；现有生产库不作为空库测试目标。

### 8.2 访问控制与运行维护

共享评审账号为可选配置，开启时页面、API、PDF、原页与接口文档都先认证。密码保存为随机盐 scrypt 哈希，账号、哈希与访问源缺项会在模型加载前失败。修改及消耗模型的请求需要标记并检查来源，认证响应限制缓存和跨站嵌入。它不是多用户权限系统，账号持有人共享文献库和现有修改能力。[11]

仓库提供 Caddy 反代示例，预期由 HTTPS 入口转发到回环后端。本机 TLS 已验证匿名拒绝、跨源写入拒绝、认证上传、Range／HEAD 等行为；独立Chromium使用随机测试凭据真实完成认证与页面资源请求，未手动操作系统密码弹窗。正式域名、证书、外网浏览器登录和长期保活由参赛者后续安排验收。此前 CPU 独立环境仅证明安装、解析与持久化，完整四卡验证另有记录，两者不互相替代。[11][13]

## 9. 限制与后续工作

当前主要限制为扫描复杂公式、跨页表格和署名版面的结构化不足；引用格式与 OCR 错字可能漏识别；来源和数值检查不覆盖完整语义。问答有基于上一有效来源的指代追问，没有长期对话记忆或流式输出；研究任务为固定有界流程，没有自主工具规划。图谱与写作主要依赖可识别书目和摘要，已有较新摘要核对入口，缺少全文相关工作审查及穷尽式查新。

核心工程、Chromium页面流程、文件下载与技术内容已完成本轮收尾，具体范围见逐项赛题核对[16]。参考文献批量下载已覆盖明确编号及arXiv中题名/作者/年份唯一匹配，阅读正文已支持悬停翻译，订阅已支持站内日/周刷新。所有出版商的无编号书目解析、全量arXiv同步、站外推送、训练式个性化推荐及基于全文证明Future Work未被解决仍未实现。后续可按失败样例扩充复杂解析与语义验证。团队真实信息待本人填写；公网和视频由参赛者负责，提交材料须对应同一真实版本。
