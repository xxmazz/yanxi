# 有界研究任务编排

2026-10-29，在探索发现页增加「研究任务」。输入主题和 1—3 篇论文的数量后，系统按固定步骤自动检索 arXiv、保存候选、逐篇入库、等待解析与版本确认，再汇总来源。页面显示过程、状态、原论文链接、阅读入口及本地模型综述状态。

## 流程与状态

- 检索复用现有官方 API 和缓存策略；中文主题复用本地 Qwen 转换。过期缓存不可直接作为自动入库的依据。
- 在官方首批最多八个候选中，本地 E5 将本次英文主题编码为 query，将候选题名与摘要编码为 passage，按余弦相似度重排；不以文献库主题相似度替代当前问题。无 E5 时明确使用官方相关性顺序。同 base arXiv 编号只选一次，跳过已归档记录。保存候选、官方原序号、相似度、检索步骤及选择依据；分数不是论文质量或相关概率，也不代表检索了整个 arXiv。
- 下载与索引复用现有有界队列。下载记录完成后仍须检查正文解析状态，只有 ready 且有效的文献才进入来源汇总。
- 相似版本需要确认时暂停为 needs_review，用户在文献库处理后可从检查点继续；不擅自覆盖版本。
- 记录原始查询、选定编号、下载任务编号、入库身份、过程与结果到 SQLite research_tasks 新表。不修改已有文献表结构；升级前已备份数据库。
- 失败、中断、待确认或待生成综述可重试，复用已保存候选、已有下载任务和已入库文献。解析失败需先在文献库重新解析。服务重启将活动研究任务标为 interrupted，等用户继续，不隐式重新启动下载或推理。
- 取消只停止后续任务步骤，已提交的单篇下载／解析正常结束，文件保留。每次最多一个活动研究任务、最多三篇论文；轮询及回调结束后检查累计20分钟预算，不会强行终止已在运行的模型线程。下载总预算改为五分钟，仍受100 MB、官方HTTPS地址和单次读取等待限制；慢速网络可能失败，可从检查点重试。
- 本地模型已加载时调用已有逐篇摘要综述及来源检查，成功结果必须通过全部所选文献的引用覆盖校验；无摘要、模型拒答或校验失败时保留原文结果，置 needs_summary，允许重试摘要，避免将部分结论作为完整综述。兼容升级前 complete 但综述不可用的旧任务，允许补生成。完成不代表全文研究或所有结论已验证，结束前重新核对文献有效状态。
- arXiv 导入的题名采用已保存的官方元数据，避免侧边 arXiv 标签被误认作题名；原文件不改写。普通本地 PDF 仍走原生题名识别。

这是基于现有工具的固定有界任务编排，尚未实现模型自主选择任意工具、动态重规划、多 Agent 协同或跨任务偏好学习。没有新增模型、云端 API 或运行依赖；任务保存与恢复不等于完整对话记忆。

## 真实验证

使用仅监听回环地址的临时 CPU 服务，正式 GPU 模型保持停止。

1. 查询 2005.11401v4，自动复用已入库 RAG 论文19页，解析状态检查后汇总来源。
2. 浏览器输入1905.07830v1，实际官方返回题名为 HellaSwag: Can a Machine Really Finish Your Sentence?。自动下载新文件、完成14页解析和BM25索引、保存官方来源并汇总。该编号不是RMSNorm，展示以官方返回题名为准。
3. 两条任务的结果 document_id 与服务器原 PDF SHA-256 一致，官方来源表包含实际 arXiv 编号；任务历史跨服务重启保留。
4. 页面清楚显示未加载本地模型，没有生成摘要综述。本轮没有使用 GPU，未验证中文主题或多篇新下载＋模型综述的 GPU 端到端流程。

121项后端测试、5项前端工具测试及生产构建通过。新增9项任务测试覆盖成功持久化、单活动任务、失败重试不重复检索／导入、版本确认后继续、取消、过期缓存拒绝、重启中断、超时、归档与汇总期间状态变化、候选去重及API验证。

真实下载两次遇到慢速网络超时，测得约20—25 KB/s；延长到五分钟预算后完成。45页报告的摘要不在首页，旧逻辑漏掉该来源，新覆盖检查将其拦为 needs_summary；修复为在前八页寻找明确摘要标题、排除目录点线项、识别编号摘要与后续小节边界。最终摘要来源分别为报告物理第5页、另一篇第1页，目录第3页和摘要第5页已通过原页图像对照。只取同页最多1400字符，不声称跨页或完整长摘要识别。图谱算法指纹升级为 references-v4，旧快照需重新生成。

新下载的两篇均完成 E5 索引（132/132、34/34段）。修复后重试复用所选文献与下载记录；最终复测复用查询缓存和已入库文献，两条中文结论均核对到各自摘要的实际方法陈述，没有据此声称临床有效性或通用性能优越。旧版 RAG 单篇「来源完成、无模型综述」任务也成功从第2次运行补生成，selected及job身份与重试前一致，无重复下载。

## 接口

- POST /api/research/tasks：query（2—240字符）、limit（1—3），返回202及任务身份。
- GET /api/research/tasks：最近20条任务。
- GET /api/research/tasks/{id}：单任务详情。
- POST /api/research/tasks/{id}/retry：从检查点继续；运行中或已有完整综述的完成态不能重试。needs_summary 及旧版综述不可用的完成记录可以补生成。
- POST /api/research/tasks/{id}/cancel：取消后续步骤。

首次CPU基础检查导入的HellaSwag当时不含E5向量。后续已通过正式GPU服务重新解析并补齐63段向量，原件、14页正文及既有版本状态不变，见[补齐记录](EMBEDDING_REPAIR_20261029.json)。模型服务在验收结束后停止，以保留GPU资源；代码与构建同步服务器，演示时需启动。

## 2026-10-30 · 历史摘要来源失效处理

GET任务列表及详情现在按所选文献核对来源指纹；同一次列表请求对相同文献范围只计算一次。完整历史若无有效摘要、原件/版本/来源已改变或文献归档，将在响应中标记needs_summary、summary_stale并隐藏旧结论和引用，数据库原记录保留。没有变化且摘要有效的任务仍为complete，不能无故重试覆盖。

通过POST重试可复用所选文献与下载检查点、重新生成失效摘要；不重新检索下载。5项新增测试覆盖指纹一致性、正文变化、归档和旧任务、API重试保护及列表缓存。联合回归先如实记录旧历史失败，再在隔离副本补生成两条摘要，5条完整历史均通过来源/原件/指纹检查；正式库历史未改写。详见[工程验收](ENGINEERING_RELEASE.md)。
