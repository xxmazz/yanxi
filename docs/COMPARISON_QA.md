# 表格数值与跨篇问答

2026-10-28 在真实 192 服务器核对官方资料包中的 Transformer v7、BERT，以及已入库的 RAG 论文。本轮修复表格数值计算被原文数字检查拦截、跨篇回答只引用一篇文献的问题。实际响应、文件哈希、原文摘录哈希和物理页码见 [验证数据](COMPARISON_VERIFICATION_20261028.json)，保留修复前失败记录。

## 实现

- 单篇明确语言方向的 BLEU 问题，先从召回原页读取 Poppler 单词坐标，区分 EN-DE、EN-FR 和重复出现的训练成本列；识别结果还须与已保存的原文逐行一致。
- 精确匹配模型行，空单元格不从相邻列补值。比较时限定为表中其他模型系列的最高值，包含集成模型，不扩展为未列出模型的历史排名。系列按模型名首词区分，表注必须明确提及该系列及先前模型／state-of-the-art。
- 使用 Decimal 计算差值，返回 `calculation` 的操作、输入、结果、列与指标；回答明确区分表中原值和程序计算值，引用连续表格原文。
- 明确选择两至六篇进行比较时，检索首先保证每篇至少一段证据，总预算仍为六段。通用路径由本地 Qwen 分别提取单篇事实，先按单篇证据检查，再合并并检查引用覆盖，缺少任何所选文献则拒答。
- 两篇架构对比另有保守谓词核对：只有原文分别明确写出编码器／解码器架构和多层 Transformer 编码器时才组织结构对比；模型名从原文读取，跨篇推断标为“归纳”。其余情况回到逐篇事实路径。

无需新增 Python 包或模型。原生表格读取依赖系统 Poppler 的 `pdftotext`（Ubuntu 安装 `poppler-utils`），复用现有本地 OCR 部署依赖。没有该命令或布局不明确时不执行结构化计算，转入普通证据问答。

## 复现

先按 [本地后端说明](LOCAL_BACKEND.md) 部署，并将官方 `1706.03762v7.pdf`、`N19-1423.pdf` 正常入库至 ready、active 状态。脚本会核对本地原件与服务器下载文件的 SHA-256，不导入、不重建索引、不更改版本选择。

```sh
.venv/bin/python -m scripts.verify_comparison_qa \
  --base-url http://127.0.0.1:18474 \
  --fixture-dir '/path/to/科研小助手' \
  --rag-id 23e3249e9a1e75418d82efecab0ea8c4d033b89c93742f63208d47ce01f21233 \
  --output runtime/comparison-verification.json
```

`--fixture-dir` 下须有 `pdf/`；省略 `--rag-id` 时只运行六个官方文件相关用例。输出保存实际响应、检查项与耗时，失败返回非零退出码。

## 边界

- BLEU 读取目前只支持已确认的原生 EN-DE／EN-FR 双列、连续单行模型表格；不支持扫描表格、跨页／合并单元格、跨行名称或任意指标。布局不支持时的普通问答仍可能错误或拒答。
- 架构规则依赖明确的英文谓词，不是通用语义蕴含判断；不根据 BERT 等名称补写知识。
- 通用跨篇路径保证分别取证并检查引用覆盖，但可能仅给出单篇相关事实，不能保证回答复杂比较问题的全部子项。最多六篇也不代表六篇充分对比验收。
- 数值、逐字引文、固定测试通过均不等于通用正确率。GPT 系列跨篇基准、真实 20 篇图谱、复杂公式／表格还原及完整赛题交付仍需推进。
