# Git 上传方式

2026-10-27 已完成 GitHub 官方 CLI 登录，并实际推送成功。仓库继续使用 `origin` 指向 `xxmazz/yanxi`。

网页上传历史与本地原始开发历史已通过合并提交连接，保留两边记录；没有 force push，也没有重写原始作者时间。此后可在当前工程直接使用正常 Git 提交与推送：

```sh
git status
git add 需要提交的文件
git commit -m "说明本次真实功能变更"
git push origin main
```

本机 Git 原先没有使用 macOS 的代理，导致 HTTPS 连接失败。本次仅在该仓库的本地 Git 配置中设置 GitHub 代理为 `http://127.0.0.1:7897`；该配置没有进入公开仓库。推送时需要本机代理运行。如果以后代理端口变化，应相应修改本地 Git 配置。

GitHub CLI 可执行文件放在本机用户目录的 `.local/bin/gh`，指向永久工具目录。认证由 CLI 管理，不在工程中存放 Token，也不需要通过聊天发送密钥。当前提交身份使用 GitHub 登录账号及其隐私邮箱。

其他机器需要独立完成认证，不应复制凭据到服务器。模型、PDF、数据库和 `.env` 都已排除在 Git 之外。新功能经过验证后按模块提交，不用空提交模拟开发进度。
